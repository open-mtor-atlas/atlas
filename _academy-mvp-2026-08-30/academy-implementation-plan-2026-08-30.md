# mTOR Atlas — Academy / Learn MVP: codebase inspection + least-invasive implementation plan

*2026-08-30. Written after a full read-only inspection of `open-mtor-atlas/atlas` @ `main`. Nothing in the repo was modified. Section numbers in **[S§n]** refer to the attached spec `mtor_atlas_academy_claude_implementation_spec_v2.pdf`.*

---

## Part 1 — What the Atlas actually is

### 1.1 There is no framework

No React, no Vue, no bundler, no `package.json` in git (it's `.gitignore`d; `node` is used only for `prerender_tabs.js`). The site is **vanilla HTML/CSS/JS generated and patched by Python**. Any Academy built with a component framework would be a second, foreign architecture. It should not be.

The site has **three rendering layers**:

| Layer | Artifact | Who reads it |
|---|---|---|
| **SPA** | one `index.html` — 3.33 MB, 6 791 lines, inline `<style>` (L74–1516), inline data consts (`ATLAS_STUDIES` etc., L2885+), 8 inline `<script>` blocks | humans + Googlebot |
| **Static pre-render** | ~390 pages under `study/`, `gene/`, `complex/`, `drug/`, `disease/`, `process/`, `outcome/`, `organelle/`, `nutrient/`, `intervention/`, `condition/`, `author/`, `question/`, `browse/`, `about/`, `data/` — generated by `build_pages.py`; plus `answers/` + `glossary/` generated by `generate.py` | AI crawlers (GPTBot, ClaudeBot, PerplexityBot…) that don't run JS |
| **Lazy module** | `pathway/pathway.js` (91 KB) + `pathway.css` (26 KB) + `model.json` (377 KB) + `contexts.json` — "Pathway & Mechanism 2.0", fetched only when the Pathway tab is first opened | humans |

`build_pages.py` is importable as a module (`if __name__ == "__main__": main()` guard at the tail), which matters below.

### 1.2 Routing

SPA routing is **hash-based, single-file, no server routes**:

```
#view=<welcome|ask|map|studies|authors|questions|lineage|about>
   &q=<search>&entity=<name>&tier=<A-D>&page=<n>&pw=<overview|explorer|guided|scenarios>
```

- `showView(which)` toggles `display` on `#welcomeView … #aboutView`; `setActiveTab()` toggles `.tab.active`.
- `applyHash()` parses `location.hash` with `URLSearchParams`; `syncURL(push)` writes it back; `popstate` re-applies. Legacy aliases (`mechanism`→`map`, `evidence`→`studies`, `events`→`about`) are handled inside `applyHash()`.
- Tabs are **`<div class="tab" data-tab="…">`, not links** — 8 of them, in `.tabs-row` (`index.html` L1584–1593).
- Static pages have their **own** navigation (`topbar_html()`), a flat `<a>` list defined by the `SITE_TABS` constant — which exists **twice, duplicated by hand**: `build_pages.py` L226 and `generate.py` L194. `build_pages.py` additionally overrides `about` to point at the static `/about/`; `generate.py` does not (small existing drift, worth fixing in passing).

**Real URLs** (`/study/DEM2016/`, `/answers/what-is-mtor/`, `/glossary/`) all come from directory + `index.html` on GitHub Pages. That is exactly the shape the Academy spec asks for **[S§4]**.

### 1.3 Styling system

Tokens live in `:root` of `index.html` (L77–108) and are **partially re-declared** in two generator templates:

| | SPA `index.html` | `build_pages.py shell()` | `generate.py STYLE` |
|---|---|---|---|
| paper / ink / soft / line | ✔ full set + dark theme | subset | subset (identical copy) |
| brand | `--teal:#A31F34` (crimson, despite the name) | same | same |
| tiers | `--tier-a…d` (equal-luminance set) | `TIER_LABEL` dict → hex | `TIER_COLOR` dict → hex |
| radius | `border-radius:0` everywhere | `3px` | `3px` |
| reading width | `.shell` 1440 px | `.wrap` **760 px** | `.wrap` 760 px |
| type | Cormorant Garamond (display) · DM Sans (body) · IBM Plex Mono (eyebrows/labels) | DM Sans + IBM Plex Mono + system fallback | same |
| body | 14 px / 1.5 | **16 px / 1.6** | 16 px / 1.6 |
| mobile | `@media 768 / 560 / 380`, sticky scrollable tab strip | `@media 760 / 560 / 380`, tables→cards | same |

**Important for [S§8]:** the static-page `.wrap` is already **760 px**, inside the spec's requested 720–780 px reading width, and body text is already 16 px/1.6. Two of the eight requested tokens therefore need no new value at all. The one genuine conflict is **card radius**: the spec asks 8–12 px, the Atlas is 0 px (SPA) / 3 px (static). The spec itself resolves this — *"not a mandate to introduce a new design system. Reuse existing Atlas tokens if they exist."* — so the plan below keeps 3 px. Flagged explicitly rather than silently.

### 1.4 Data model

| File | Records | Shape |
|---|---|---|
| `atlas_data/studies_baked.json` | **352** | `id, sid, title, authors, year, journal, category, model, finding, tier, pyramid, peer, doi, abstract, pmid, pmcid, ai_intervention, ai_target, ai_species, ai_effect` |
| `atlas_data/entities_baked.json` | **120** | `id, name, type, desc, desc_beginner, synonyms, studies[]` — types: Gene/Protein 55, Drug 17, Biological process 12, Disease 9, Pathway/Complex 9, Outcome 7, Nutrient/Metabolite 5, Intervention 3, Condition 2, Organelle 1 |
| `atlas_data/gaps_baked.json` | 10 | Open Questions / hypotheses → `/question/<slug>/` |

| `pathway/model.json` | 88 nodes · 119 interactions · **11 routes** | see below |

Entity pages exist only for entities with **≥ 3 studies** (`PAGE_THRESHOLD`), so a lesson must not link an entity URL blindly — `build_pages.py` already has the `haspage` set and `ent_ref()` helper for exactly this.

Everything the first three lessons need is already there: **Rheb** (16 studies, `/gene/rheb/`), **TSC1/TSC2** (33, `/gene/tsc1-tsc2/`), **mTORC1** and **mTORC2** (`/complex/mtorc1/`, `/complex/mtorc2/`), RAPTOR, RICTOR, Rag GTPases, lysosome (`/organelle/lysosome/`), leucine, arginine, autophagy. Landmark SIDs are present and dated: `INO2002`, `INOK2003`, `GAR2003`, `SAU2003`, `SAR2004`, `GUE2006`, `SAN2008`, `DEM2016`, `WOL2015`, `LAW2019`.

### 1.5 Guided Routes — the single most important finding

Guided Routes are **not pages and have no URLs**. They are one of four *modes* inside the Pathway tab, implemented in `pathway/pathway.js` (`renderGuided()`, §3 "GUIDED ROUTES", L924–1105) over `model.json → routes[]`.

The 11 routes are extraordinarily rich, and they are the Academy's raw material:

```
aa       How does a cell know it has enough raw material to grow?        7 steps
gf       How does a cell learn that it is allowed to grow?               8
rapa     Why doesn't rapamycin switch mTOR off completely?               7
out      What does a cell actually do when mTORC1 fires?                 7
energy   How does a cell decide it cannot afford to grow?                6
mtorc2   Why does one kinase need two complexes?                         6
clin     Does any of this actually help a patient?                       8
exercise Why does lifting something heavy make a muscle bigger?         10
fasting  What happens, and in what order, when you stop eating?         12
open     Where does this pathway stop being known?                      12
cancer   Why does a pathway we understand this well only half work…?    12
```

Each route carries `name` (already phrased as a **question**), `territory`, `summary`, `story`, `journey` (title/question/…), `spine[]`, `interactions[]`, and `steps[] = {interaction, what, why}`. The spec's lesson architecture **[S§11]** — Question → Core idea → Mechanism → Evidence → Think → Go deeper — is nearly isomorphic to this. The Academy is not a new content system; it is a **reading surface over content that already exists**, plus three hand-written lessons.

**The gap:** the deepest addressable URL today is `/#view=map&pw=guided` — it opens Guided mode on whatever route is first. There is no way to link *"→ follow the Rheb route"*. `PathwayApp` already exposes `boot()`, `setMode()` and `focusNode()`; a `route` hash param plus an `openRoute(id)` entry point is ~12 lines and breaks nothing. See §2.6.

### 1.6 The deploy pipeline is a minefield — and it is documented as one

`deploy.bat` (24 KB, Windows-only, the supported path) runs, in order: git-lock housekeeping → `reconcile_with_origin.py` → deploy.bat self-drift gate → `stamp_updated.py` → `sync_airtable.py` → `build_chunk_index.py` → **`build_pages.py`** → `verify_prerender.py` → `validate_claims.py --strict` → `verify_index_html.py` → backup index.html → `git reset origin/main` → restore → verify → `git add` → commit → push.

Three consequences that constrain the plan:

1. **`git add` uses an explicit allowlist of folders** (L404: `for %%D in (study gene complex drug disease outcome process intervention nutrient organelle condition author question browse answers glossary about data)`). A new `academy/` folder **not added to that loop never reaches the live site** — and the file's own comments record that this has already happened twice (`condition`/`organelle` sat untracked for 11 days; `events_baked.json` was silently reverted every deploy). This is a hard requirement, not a nicety.
2. **`git reset origin/main` runs mid-deploy.** Only files named in the `git add` lists (or already tracked, via the `git add -u` backstop) survive. New generator scripts must be listed too.
3. **Gates that will see Academy content:** `validate_claims.py --strict` scans `index.html` prose for absolute language (rule R5: *proves / definitive / settles / avoids*) and tier-scope overclaims (R6). `check_tier_palette.py` bans borrowing tier colour variables across unrelated meanings. `verify_index_html.py` refuses to ship a truncated `index.html`. Any Academy prose placed **inside `index.html`** enters the claim linter; prose in a separate file currently does not — which is an argument for extending the linter, not for dodging it **[S§17]**.

## Part 2 — The plan

### 2.0 The single architectural decision

> **Build the Academy as a fourth static-generated section (`build_academy.py` → `/academy/…`), not as a ninth SPA view.**

Why this is the least invasive option:

- The spec asks for real paths `/academy/core/rheb` **[S§4]**. The SPA is hash-routed; giving it real paths means either a router rewrite or 404s. The static layer already produces exactly this URL shape.
- `index.html` is a 3.33 MB single file with a documented history of write-corruption, three deploy gates guarding it, and a claim linter reading its prose. Every byte not added to it is risk avoided. The Academy needs **one line** in it.
- `generate.py` is the precedent, and its own docstring states the pattern: *"Pure additive static content — does not touch index.html, build_pages.py, or any Airtable-driven TYPE_DIR."*
- Lessons are prose + evidence + one diagram. There is no cross-view state that would justify SPA machinery. Progress is one `localStorage` key.
- GEO/SEO: the project's entire strategy is that AI crawlers can read the site without JS. Academy pages would be text-first, evidence-linked, question-headed — the highest-value crawler content the site could add. Inside the SPA they would be invisible to ClaudeBot and GPTBot.

Everything below follows from this.

### 2.1 New files (all additive, none touch existing behaviour)

```
build_academy.py                  generator; imports shell(), topbar_html(), tier_bits(),
                                  slugify(), e(), DATASET_REF, SITE from build_pages.py
academy_data/lessons.json         the AcademyLesson records  [S§16]
academy_data/modules.json         curriculum ordering (module → lesson ids, level, minutes)
academy/index.html                Academy homepage           [S§5]      ← generated
academy/core/index.html           mTOR Core curriculum       [S§6]      ← generated
academy/core/what-is-mtor/index.html                         [S§12]     ← generated
academy/core/mtorc1-vs-mtorc2/index.html                     [S§13]     ← generated
academy/core/rheb/index.html                                 [S§14]     ← generated
sitemap-academy.xml                                                     ← generated
verify_academy.py                 link/SID/entity integrity gate
```

**`lessons.json` record** — spec **[S§16]** exactly, with the "prefer existing Atlas IDs" rule made literal:

```jsonc
{
  "id": "L03", "slug": "rheb", "module": "core",
  "title": "Rheb — The Critical Regulator",
  "subtitle": "How a small GTPase helps control mTORC1",
  "level": "Core", "estimatedTime": 25,
  "question": "How does a small GTPase help control mTORC1?",
  "coreIdea": "…",
  "sections": [ {"kind":"mechanism","heading":"…","body":"…","figure":"rheb-spatial"} ],
  "concepts":  ["GTP/GDP cycling", "GAP", "lysosomal localisation"],
  "proteins":  ["RHEB", "TSC1/TSC2", "MTOR"],        // → entities_baked.json names
  "pathways":  ["mTORC1"],
  "studies":   ["INOK2003", "GAR2003", "SAU2003", "INO2002", "DEM2016"],  // → sid
  "authors":   [],                                    // → author_bios_baked.json keys
  "guidedRoutes": ["gf", "aa"],                       // → model.json routes[].id
  "thinkQuestions": [
    {"prompt": "What would you expect if Rheb were predominantly GDP-bound?",
     "reveal": "…"},
    {"prompt": "What experiment could distinguish whether regulation depends mainly on nucleotide state, localisation, protein abundance, or a combination?",
     "reveal": "…"}
  ],
  "previousLesson": "mtorc1-vs-mtorc2", "nextLesson": "tsc-and-rheb"
}
```

The lesson stores **only IDs**. Titles, years, tiers and one-line findings for the Evidence section are resolved at build time from `studies_baked.json`, and entity links from `entities_baked.json` + the `haspage` set. **No scientific record is ever duplicated** — this satisfies **[S§11] "Do not duplicate study records"** and **[S§19] "No duplicate scientific database is created"** structurally, not by discipline.

### 2.3 Page templates

All three page types go through `build_pages.py`'s existing `shell(title, desc, canonical, jsonld, body, breadcrumb, active_tab)`. That gives, for free: the topbar, breadcrumb, footer, mobile media queries, fonts, GA tag, OG/Twitter meta, canonical. **`build_academy.py` writes only the `body` string and the JSON-LD**, plus one extra `<style>` block appended for Academy-specific classes.

**Academy homepage `/academy/`** **[S§5]** — hero ("mTOR Academy" / "From understanding mTOR to thinking like a researcher." / sublede / `Start learning →`); "Your path" rail; two entry cards (Learn · Guided Routes) + a third disabled "Research Challenges — coming soon"; curriculum preview showing the first three lessons; bottom bridge back to Studies · Pathways · Authors · Proteins. JSON-LD: `Course` + `BreadcrumbList`, `isPartOf: DATASET_REF`.

**Curriculum `/academy/core/`** **[S§6]** — module title + one-line description, then a plain ordered list: state glyph (`✓` done / `●` current / `○` locked-but-visible), number, title, level, minutes. Lessons 04–10 are listed with their titles and marked *in preparation* — the curriculum is honest about what exists. JSON-LD: `Course` with `hasPart: [CourseInstance…]`.

**Lesson `/academy/core/<slug>/`** **[S§11]** — fixed order: **Question → Core idea → Mechanism (diagram) → What does the evidence say? → Think → Go deeper → Next lesson**. Two-column at ≥ 1000 px: 760 px reading column + a 230 px sticky right rail ("In this lesson" anchor list, and a compact contextual pathway strip highlighting the current concept). Below 1000 px the rail collapses to a horizontal `<details>`-style "In this lesson" list above the body — **[S§10]**, and no horizontal overflow at any width, matching the existing `overflow-wrap` + 44 px touch-target rules already in `shell()`. JSON-LD: `LearningResource` + `FAQPage` (from `thinkQuestions`) + `BreadcrumbList`.

**Evidence cards** **[S§11]**: 3–5 per lesson, each = title · year · tier badge (colour strictly from `tier_bits()`, never a new hex — `check_tier_palette.py` rule 6) · the study's own one-sentence `finding` · `→ /study/<SID>/`. Rendered from `studies_baked.json` at build time.

**Think component** **[S§11]**: question first, a `Think first` / `Reveal` pair. Implemented with `<details>` — works with zero JS, works for crawlers, works with the existing `prefers-reduced-motion` rule. Never scored, never "correct/incorrect".

**Diagrams**: inline SVG, hand-authored per lesson, monochrome + `--teal` accent, `role="img"` + `<title>`/`<desc>`, sized in `em` so they scale with the reading column. No library, no network request, no cartoon biology **[S§7]**.

### 2.4 Progress UI

One `localStorage` key, `atlas-academy-progress` → `{"L01":"done","L03":"reading"}`, following the exact pattern of the existing `atlas-theme` and `atlas-level` switches (try/catch, silent fallback). ~30 lines of inline JS shared by the three page types. Marks the curriculum glyphs and the homepage "Your path" rail. **No XP, no badges, no streaks, no certificates** **[S§2, S§18]**.

### 2.5 Atlas → Academy cross-link **[S§15]**

`build_academy.py` writes `academy_data/_sid_to_lesson.json` (reverse index, ~15–25 SIDs for three lessons). `build_pages.py`'s `study_page()` reads it if present and, after *Related topics*, appends:

```html
<h2>Learn the biology</h2>
<p>Want to understand the biology behind this study?
   → <a href="/academy/core/rheb/">Rheb — The Critical Regulator</a></p>
```

Optional, additive, absent when the SID maps to no lesson. Study pages are not redesigned. Ordering note: `build_academy.py` must run **before** `build_pages.py` for the reverse index to be fresh; on a first-ever run the block simply doesn't appear, which is safe.

### 2.6 Guided Route deep-links — the one decision that needs your call

Lessons need *"→ follow the guided route: How does a cell learn that it is allowed to grow?"*. Today that link can only be `/#view=map&pw=guided`, which lands on whichever route is first.

- **Option A (zero code):** link `/#view=map&pw=guided` and name the route in the link text so the reader picks it. Works today, mildly clumsy.
- **Option B (recommended, ~12 lines):** add an optional `route` hash param. In `showView()`'s `PATHWAY-2.0-BOOTSTRAP` block, read `p.get('route')` alongside the existing `pw`; add `openRoute(id)` to the `window.PathwayApp` export next to the existing `focusNode(name)` — which is the same pattern, already shipped and proven. Old URLs keep working unchanged; the param is purely additive; **[S§4] "Keep existing Guided Route URLs unchanged"** is satisfied because `#view=map&pw=guided` continues to behave exactly as it does now.

Option B also gives the Academy homepage's "Guided Routes" entry card something real to point at, and makes the 11 routes individually shareable — a GEO win independent of the Academy.

### 2.7 Scientific-content gate **[S§17]**

Academy prose is exactly the kind of writing the project already lints. Recommendation: extend `validate_claims.py` with an `academy_data/lessons.json` pass reusing the existing R5 (absolute language) and R3 (mechanistic work described as clinical evidence) scanners, and wire it into the same `--strict` deploy gate. This is the project's own standard, applied to new prose, and it costs ~20 lines because the scanners already exist and are text-based.

Editorial rules baked into the lesson template rather than left to memory: every mechanistic claim in *Mechanism* must have at least one SID in *Evidence*; simplifications carry an explicit "this is a teaching model" line **[S§17.1]**; the *Go deeper* section always names at least one open question or `/question/<slug>/` page, so uncertainty is visible on every lesson, not just the ones about uncertainty.

### 2.8 Build order

Mapping **[S§20]** onto this repo:

1. ~~Inspect the codebase~~ — done, Part 1.

5. Academy homepage + curriculum page.

9. Regression pass (§2.9). **Only then** lessons 04–10.

Steps 2–7 are individually revertable; nothing before step 8 can reach production.

### 2.9 Acceptance & regression checks **[S§19]**

Automated (`verify_academy.py`, run in the deploy gate):

- every `studies[]` SID exists in `studies_baked.json`; every `proteins[]`/`pathways[]` name exists in `entities_baked.json`; every entity link points at a page that `build_pages.py` actually generates (≥ 3 studies); every `guidedRoutes[]` id exists in `pathway/model.json`; `previousLesson`/`nextLesson` resolve; no internal link 404s; every generated Academy page carries its H1 and its Evidence section in **static HTML with JS disabled**.

Manual:

- all 8 existing tabs still switch; `#view=studies&tier=B&page=2` still restores state; back/forward still work; `/study/DEM2016/`, `/gene/rheb/`, `/answers/what-is-mtor/`, `/browse/` unchanged apart from the extra nav item; `verify_index_html.py`, `verify_prerender.py`, `validate_claims.py --strict`, `check_tier_palette.py` all still pass; Academy at 360 px / 768 px / 1440 px with no horizontal overflow; dark mode — **note:** the static layer has *no* dark theme today (only the SPA does), so Academy pages will be light-only like every other static page. Consistent, but worth knowing.

### 2.10 Explicitly out of scope **[S§2]**

AI tutor · badges/XP · certificates · adaptive learning · experiment builder · personal research notebook · knowledge graph visualisation · hypothesis management · Research Challenges (homepage card only, disabled) · lessons 04–10 (listed in the curriculum, marked *in preparation*).

## Part 3 — Three things worth knowing before we start

1. **The Guided Routes are better content than most textbooks, and they are currently reachable only by clicking into a tab and guessing.** Whatever else the Academy does, giving those 11 questions their own addressable, linkable, crawlable surface is the highest-value part of this work. §2.6 Option B is 12 lines.
2. **`deploy.bat`'s folder allowlist is the single most likely way this ships and then silently doesn't.** It has already bitten this repo twice, both times documented in the file's own comments. It is step 8, and it is not optional.
3. **The spec's design tokens and the Atlas's design system disagree in exactly one place** — card radius 8–12 px vs the Atlas's 0/3 px sharp corners. The spec defers to the Atlas **[S§8]**, so the plan keeps 3 px. If you actually want the softer Academy look, say so now: it is a one-constant change *before* the pages exist, and a visual-consistency argument afterwards.
